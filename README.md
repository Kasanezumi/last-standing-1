# Last Standing 1（ラストスタンディングワン）

2〜100人で遊べるオンライン対戦の動作版です。公開先は未設定です。既存のSites上のCPU対戦版とは別のアプリです。

## このPCで起動

1. ZIPを展開し、`START.cmd`をダブルクリックします。
2. ブラウザーで <http://127.0.0.1:4080> を開きます。
3. 名前を入れて「ルームを作成」を押し、6文字のコードを参加者へ伝えます。
4. 別のブラウザー画面から同じURLを開き、コードを入力して「参加」を押します。
5. 参加者全員が「準備OK」を押すと開始します（BOTなしは2人以上必要）。

サーバーのウィンドウは対戦中、開いたままにしてください。停止はCtrl+Cです。ポートが使用中なら、既に起動しているサーバーを利用するか、既存のサーバーを停止してから起動してください。

ZIPにはWebSocketライブラリを同梱しています。Node.js 22以降が必要です。このPCではCodex付属のNode.jsも自動検出します。ソースだけを移す場合は `npm install` または `pnpm install --frozen-lockfile` の後、`node server.mjs` で起動できます。

## クイックマッチ

「クイックマッチ」を押すと、募集中の公開ルームへ自動参加します。なければ新規作成し、BOTなしでは2人以上の参加と全員の「準備OK」で5秒の準備カウントダウンを開始します。人数や経過時間だけで開始することはありません。「退出」でキャンセルできます。通常のコード指定ルームとは別にマッチングします。試合終了後はもう一度「クイックマッチ」で次の相手を探せます。同じサーバーに接続した人同士が対象です。

## BOT補充オプション

参加前に「不足人数をBOTで補充（100人）」を有効にしてください。クイックマッチ・コード指定ルームとも、人間の参加者全員が「準備OK」を押すまで開始しません。全員の承認後に不足人数をBOTで埋め、5秒の準備時間後に開始します。承認は開始前なら取り消せます。追加参加者も承認が必要で、次の試合では全員が再承認します。BOT補充あり／なしは別々にマッチングします。コード指定ルームでは作成者の設定が全員に適用され、1人から開始できます。BOTはサーバー側で移動・攻撃・ガード・ジャンプ・投げを行い、通常の体力と判定で戦います。試合開始後にBOTと人間の入れ替えは行いません。

## 遊び方

- 方向キー／WASD：移動・ジャンプ・しゃがみ。後ろ入力でガード。
- J/K/L：弱・中・強パンチ。U/I/O：弱・中・強キック。
- J＋U または H：投げ。コントローラーでは X＋A／□＋×、またはLB／L1。
- 気功弾：↓↘→＋パンチ。昇天拳：→↓↘＋パンチ。旋風脚：↓↙←＋キック。左向きでは左右反転。
- 体力200。開始前5秒は移動・しゃがみ・ジャンプのみ可能。最後の1人が勝利。
- 開始10秒後からエリア縮小し、60秒後に最小サイズ（幅460）になります。185秒後は全員が継続ダメージを受けるサドンデスです。
- 主催者が退出すると、接続中の別プレイヤーへ主催権が移ります。
- オンライン中は一時停止できません。画面を離れると入力は解除されますが、対戦は続きます。
- 短時間の通信切断は15秒以内に自動再接続します。ページの再読み込み・ブラウザー終了では復帰情報が失われ、試合中の再参加はできません。
- CPU対戦・トレーニングもモード選択から利用できます。

## インターネットへ公開する場合

継続実行できるNode.jsサーバーと、HTTPS/WSSを利用できる公開先が必要です。このアプリを丸ごと同じドメインで配信します。静的ファイルの配置だけではオンライン対戦は動きません。

- 起動コマンド：`node server.mjs`
- `HOST=0.0.0.0`：外部インターフェースで待ち受ける場合に指定。既定値はこのPCのみの `127.0.0.1`。
- `PORT`：既定値4080。公開サービスから指定されるポートに対応します。
- `MAX_ROOMS`：既定値10。1ルーム最大100人ですが、同時に10試合を実運用できる性能を保証する値ではありません。
- `ALLOWED_ORIGINS`：フロントを別ドメインに置く場合のOrigin許可リスト（カンマ区切り）。通常の同一ドメイン構成では不要です。
- リバースプロキシは `Host` とWebSocket Upgradeヘッダーを正しく転送し、長時間のWebSocket通信を許可してください。
- ヘルスチェック：`GET /health`。
- Dockerで動かす場合は同梱のDockerfileを利用できます。Dockerでの実行確認は未実施です。

現在は単一サーバー方式です。複数プロセス・複数台への水平分散には対応していません。ルームと試合はメモリー上にあり、サーバー再起動で終了します。外部公開前にはHTTPS、ホスティング先の接続数・転送量・CPU上限を確認し、その環境で負荷試験を行ってください。アカウント制のマッチメイキング、ランキング、チート検知、観戦専用入室は未実装です。

## 検証

`node --test test/*.test.mjs`

100本の実WebSocket接続を使った同一ルーム参加・入力・試合開始・再接続のローカル試験、および戦闘ロジックの試験を実施しました。ブラウザー2画面でもルーム作成・参加・開始を確認しています。100人が別々の回線から参加するインターネット環境での遅延・負荷検証は未実施です。

物理演算60Hz、全員への状態送信15Hz。クライアントが送るのは操作入力のみで、体力、座標、攻撃判定、勝敗はサーバーが決めます。通信状態は配列に圧縮し、表示では補間します。完全なロールバック方式ではないため、通信遅延は操作感に影響します。

第三者ライブラリ：ws 8.21.3（MIT）。ライセンスは `node_modules/ws/LICENSE` に同梱しています。

## 脱落後の幽霊観戦

オンラインで脱落すると、自分の画面だけに半透明の幽霊が表示されます。方向キー／WASD／コントローラーの方向入力で上下左右へ移動し、カメラと全体マップ表示が追従します。攻撃・当たり判定・境界ダメージはありません。幽霊の位置はサーバーへ送信されず、他の参加者には表示されません。次の試合で通常のキャラクターに戻ります。

## CPU戦

モード選択で「CPU戦（1人＋99体）」を選び、開始ボタンを押すと、サーバーの参加者を待たずに1人で遊べます。5秒の準備カウントダウン後に開始します。CPU戦では一時停止が可能です。

## 参加者のキック

部屋主の参加者一覧に「キック」が表示されます。確認後、対象を退出させます。キックは試合開始前と終了後のみ可能です。開始カウントダウン中・対戦中はキックできません。キックされた参加者は自動再接続しません。自分自身とBOTは対象外です。キック後は残った参加者の準備承認をリセットします。アカウントによる入室禁止ではないため、待機中のルームへ再度参加することは可能です。

## 開始承認オプション

作成前の「全員の準備OKを待つ」（初期値ON）で設定します。ONは全員承認後、OFFは通常ルームなら部屋主の開始操作、クイックマッチなら必要人数が揃って10秒後に開始します。どちらも開始前の5秒カウントダウンがあります。参加者は部屋の設定に従い、入室後は変更できません。クイックマッチは同じ設定同士で組み合わせます。

## CPUの強さ

「CPUの強さ」で、やさしい／ふつう／むずかしいを選べます。判断間隔、攻撃頻度、ガード・投げの積極性を調整し、体力・攻撃力は共通です。CPU戦は次の試合から反映、オンラインBOTは部屋作成時に固定され、参加者全員に共有されます。BOTありのクイックマッチは同じ難易度同士で参加します。
